# POLE STUDIO — versione finale gratuita per iPhone e allievi

Questa versione è composta da **due elementi distinti** per mantenere privati i tuoi contenuti prima della pubblicazione:

- **SITO-GITHUB**: contiene l’app e un catalogo pubblico inizialmente VUOTO. Da caricare in un repository GitHub Pages pubblico.
- **ARCHIVIO-PRIVATO**: 298 voci, 57 immagini rappresentative ricavate da materiali forniti, 6 modelli di lezione modificabili. **NON caricare il file privato su GitHub.**

## 1. Creare l'app senza pagare

1. Crea un nuovo repository pubblico su GitHub, ad esempio `pole-studio`. Non modificare il repository di Agenda Mia.
2. Estrai `PoleStudio-SITO-per-GitHub.zip`.
3. Seleziona tutti i file presenti dentro la cartella estratta e caricali in GitHub con **Add file → Upload files**. `index.html` deve essere nella cartella principale.
4. Premi **Commit changes**.
5. Vai in **Settings → Pages**; scegli **Deploy from a branch → main → /(root)**; premi Save.
6. Apri l'URL GitHub Pages sul Mac e sull'iPhone; da Safari premi **Condividi → Aggiungi alla schermata Home**.

## 2. Importare il tuo catalogo privato una sola volta

1. Trasferisci `PoleStudio-ARCHIVIO-PRIVATO-298-figure.json` sull'iPhone (AirDrop, iCloud Drive o File). **Non pubblicarlo**.
2. Apri Pole Studio sul tuo iPhone, entra nell'area insegnante (`index.html`).
3. Vai in **Impostazioni → Ripristina da backup**.
4. Seleziona il file privato e conferma l'importazione. Vedrai le 298 schede e i 6 modelli di lezione.
5. Da quel momento modifica nomi, livelli, fotografie, punti di contatto, tecnica, errori, note e progressioni direttamente nell'app.
6. Conserva regolarmente un backup in File o iCloud Drive: i dati restano sul dispositivo.

## 3. Condividere solo quello che vuoi

1. Apri la sezione **Condividi** dell'area insegnante e spunta le figure e le lezioni da mostrare.
2. Premi **Scarica catalogo.json**.
3. Carica SOLO questo `catalogo.json` aggiornato nella radice del repository GitHub. Non caricare il file privato.
4. GitHub Pages pubblicherà il catalogo; manda agli allievi il link `https://TUO-UTENTE.github.io/pole-studio/allievi.html` (il link completo è mostrato nell'app).
5. Gli allievi potranno consultare le schede e scegliere lo stato **Non iniziata / In studio / Padroneggiata**.
6. Le modifiche dell'insegnante non si sincronizzano automaticamente: ripeti esportazione/caricamento di `catalogo.json` quando vuoi aggiornare il materiale.

## 4. Livelli, figure e immagini

- **298 voci** ricavate dalle schermate fornite, dagli schemi PDF della docente e da qualche integrazione di base.
- **57 illustrazioni/fotografie** rappresentative delle figure o degli esercizi associati. Le figure rimanenti hanno volutamente un campo immagine vuoto: le schermate originali riportano un lucchetto al posto della posa. Non abbiamo inventato pose diverse.
- **8 schede** hanno istruzioni tecniche preliminari, derivate da passaggi leggibili del PDF e da alcune figure di base; le altre sono segnate **Da completare e verificare** perché dal solo nome non si può dedurre in sicurezza la presa o la sequenza.
- I livelli 1–5 sono i livelli delle **schermate di riferimento**, non corrispondono automaticamente ai livelli CSEN.
- Il percorso didattico proposto è ispirato ai moduli di sicurezza, riscaldamento, metodologie di insegnamento, spotting e progressioni CSEN. Non è una pubblicazione CSEN né una certificazione di correttezza delle figure.

Programmi di riferimento: https://www.csenfirenze.it/corso/istruttore-pole-dance/ e https://www.csenvenezia.it/view/evento/istruttore-pole-dance-1-livello e https://www.csennapoli.it/avada_portfolio/istruttore-pole-dance-prmo-livello/.

## 5. Privacy, sicurezza, limiti gratuiti

- GitHub Pages con repository pubblico non è adatto a dati riservati degli allievi: non pubblicare elenchi con nomi, note sanitarie, fotografie di minori senza le relative autorizzazioni o materiali senza diritto di condivisione.
- L'**area insegnante non è protetta da password**: è un editor che salva i dati solo sul telefono su cui è aperto. I visitatori non possono modificare il tuo archivio locale a distanza, ma questa soluzione non è adatta a un vero sistema con account e autorizzazioni.
- I progressi degli allievi rimangono sul proprio dispositivo, senza sincronizzazione automatica e senza visualizzazione per l'insegnante.
- Il limite upload via browser di GitHub è 25 MiB per singolo file: se il catalogo cresce molto con le fotografie, sarà necessario ridurne il peso.
- Conserva sempre backup privati; cancellare i dati di Safari può cancellare i contenuti inseriti.
- Controlla sempre che l'immagine descriva la stessa variante tecnica e che tu possa condividerla legalmente prima di pubblicarla agli allievi.

## 6. Cosa modificare per prima

1. Apri una figura con una foto/disegno e conferma la correttezza della variante.
2. Aggiungi le descrizioni tecniche alle schede marcate Da completare e verificare, verificandole con un insegnante competente.
3. Duplica uno dei 6 modelli di lezione e adattalo a un gruppo o una data concreta.
4. Spunta come pubbliche solo le schede complete e adeguate agli allievi.
